# ADR-0009: 任务依赖采用同域规则（禁止跨项目无效依赖）

- 状态：Accepted
- 日期：2026-08-15
- 决策人：Developer（Node 后端分线，经主协调 agent 授权范围「防止任务自依赖、
  循环依赖、跨项目无效依赖和不存在的前置任务」）

## 背景

任务依赖（`Task.dependencies`）此前仅校验自依赖 / 重复 / 依赖存在性 / 循环依赖
（BFS），未校验**依赖任务与当前任务是否属于同一项目**。由此产生两类无效引用：

1. 项目 A 的任务依赖项目 B 的任务（跨项目耦合，删除 A 项目时 B 的任务引用悬空，
   级联清理逻辑被迫跨集合扩散）；
2. 收件箱任务（`projectId = null`）依赖某项目任务，或项目任务依赖收件箱任务
   （收件箱语义被污染，项目隔离失效）。

删除策略（项目永久删除 cascade / 任务删除）依赖「依赖必然同域」这一不变量：
cascade 删除项目时，其任务与依赖者同项目、一并删除，无需跨项目清理。

## 决策

**任务依赖必须是「同域」依赖**：

- `projectId` 完全一致才允许依赖：同一项目内的任务可互相依赖；
- 收件箱任务（`projectId = null`）只能依赖收件箱任务（`null` 与 `null` 视为同域）；
- 禁止：跨项目依赖、收件箱 ⇄ 项目任务依赖。

实现位置（`apps/api/src/modules/tasks/tasks.service.ts`）：

- `create`：按 `dto.projectId` 的最终值校验依赖；
- `update`：以**更新后的最终状态**校验——`projectId` 与 `dependencies` 可能同时
  变更，也可能只改其一（只改 `projectId` 时仍需校验既有依赖与新项目域一致）；
- 校验在 BFS 遍历依赖图时读取依赖任务的 `projectId` 并与目标域比对，一次查询完成
  存在性 + 同域双重校验，错误信息明确给出「跨项目依赖不允许」。

数据导入（`data-import` 模块，见 ADR-0006）沿用同一规则：导入快照内的任务依赖
同样强制同域，保证导入后不产生悬空/跨项目引用。

## 后果

- 正向：依赖图自包含于项目（或收件箱域），项目永久删除 cascade 时无需处理
  「外部任务依赖本项目任务」的清理分支；删除/归档语义更可预测；导入校验与
  在线校验规则完全一致。
- 负向：此前合法的「收件箱任务依赖项目任务」被拒绝（API 行为收紧，测试同步
  更新）；`projects.spec.ts` 中「外部任务依赖项目任务 + 级联清理」用例改写为
  「跨项目依赖返回 400」。
- 迁移路径：已有数据若存在跨项目依赖（在线约束下不应存在），导入/在线校验
  会拒绝其变更；如需修复，手动调整依赖归属后再更新。

## 替代方案（已评估）

- **仅禁止「项目任务依赖其他项目任务」，收件箱可依赖任意**：收件箱 ⇄ 项目
  耦合仍存在，删除项目时收件箱任务引用悬空，清理逻辑无法收敛。弃。
- **允许任意跨项目依赖，删除时全库清理引用**：当前 `disposeByProject` /
  `remove` 已实现全库 `$pull`，但语义混乱、事务范围大。弃（保持收紧）。
